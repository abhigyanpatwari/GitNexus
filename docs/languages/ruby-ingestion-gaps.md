The typed plain and safe-navigation chains resolve. Before RUBY-01 was fixed, the baseline recorded YARD parameter bindings landing on Module scope: a typed sibling could lend its type to an untyped parameter with the same name, in either declaration order, and fresh probes using the same `svc` parameter reproduced the wrong `User.save` edge from the untyped sibling in both orders (see the audit receipt). `rubyBindingScopeFor` now keeps `@type-binding.parameter` on the declaring method; [ruby-yard-param-scope.test.ts](../../gitnexus/test/integration/resolvers/ruby-yard-param-scope.test.ts) pins typed/untyped siblings in both declaration orders against the exact owner ID with a decoy `save`, and carries the review corpus below as pin-only expectations. The benchmark keeps its distinct parameter names so each cell measures its own spelling.

### Boundaries chosen for precision (missing beats wrong)

- A YARD `@param` types only a name that is one of the method's formal parameters and that the body never REBINDS — binding-target semantics: the name itself, or the name reached through a destructuring list / splat (`a, user = …`, `(a, user), b = …`, `a, *user = …`), `||=`/`+=`, `for`, `rescue =>`, a `case … in` / `=>` / `in` pattern (array/find/hash/as/splat patterns and the hash shorthand `{user:}`). A write INTO the parameter (`user.name = x`, `post.user = user`, `self.user = user`, `user[0] = 1`, `@cache[user.id] = user`, `user.count += 1`, `user&.name = x`, `user.a, user.b = …`), a block-parameter default reading it (`|x, y = user|`), a pinned `^user` or `^(user)`, and a read inside a nested block or lambda do NOT decline the tag (an assignment nested inside a pinned expression is a corner accepted unseen). In the method scope the tag's fact (strength 2) outranks a local's constructor-inferred type (strength 1), so without this a `# @param user [AuditLog]` would retype `user = User.new; user.save` as `AuditLog#save` (before the pin the local won by scope order) and a doc-drifted tag would type a name it never described. A declined tag types nothing. A block `|user|`, a block local `|x; user|`, a lambda `->(user)` or a nested `def inner(user)` no longer declines the outer tag (RUBY-03): each lists its parameters on its own scope, where the receiver walk stops, so an untyped `user` inside it stays untyped and the tagged `user` beside it keeps `User#save`. A stabby-lambda default has a separate scope for referenced parameters declared before that expression, including its own parameter. Later parameters do not shadow earlier defaults. These scopes keep an untyped lambda parameter from borrowing the outer tag without declining the tag itself.
- Not guarded (documented gaps, the tag stays): a regex named capture `/(?<user>…)/ =~ s`, `binding.local_variable_set(:user, …)`, `eval`.
- With the tag declined, a rebound parameter resolves exactly as its untagged twin (and main) does: `user = AuditLog.new; user.save` → `AuditLog#save`, `user = UserDecorator.new(user); user.full_name` → `UserDecorator#full_name`, `opts = Options.new(opts); opts.save` → `Options#save`, `user = user.account; user.save` → no edge. A call before the rebinding (`user.save; user = AuditLog.new`) keeps the pre-existing flow-insensitive answer, the local's type (`AuditLog#save`, as on main and for the untagged twin); letting the tag win would get that order right but every reassign-then-use idiom above wrong.
- A YARD `@param` types the parameter and nothing else. `@user = user` in `initialize` does NOT type `@user`, so `@user.save` in a sibling method stays unresolved (as on main), and the `attr_reader :user` forms no longer resolve: `holder.user.save`, and inside the class the bare `user.save` and `self.user.save`. Main resolved those only through the leaked class-scope `user` binding that also produced the wrong sibling edges. A YARD `@return` on a hand-written reader still types its chain, and so does one on an `attr_reader`, except when the annotated `attr_reader` is the first statement of the class body (pre-existing: `findFollowingAttrCall` lacks the `body_statement` descent that `findFollowingMethod` has). `@user = User.new` still binds the field through the constructor pattern.
- Explicit `target()`, `target(1)` and `target 1` calls beside a same-named parameter dispatch through the enclosing class's `self` binding. The Ruby provider preserves call arity and removes the generic receiver-less callable-cell invocation: Ruby invokes a callable local through `.call` or `.()`. This also closes the previous same-named method-parameter gap. Bare `target` reads are filtered during capture by [Bare identifier reads](#bare-identifier-reads-ruby-04-fixed) (RUBY-04); the lexical name also prevents free-call fallback from treating the parameter as a method.
- Pre-existing, unchanged: a method-local that gets no type binding at all (e.g. `user = 42`) walks to outer scopes for its type. Parameters are lexical names since RUBY-03; locals are not: in a block, a name the enclosing scope already binds is that scope's variable, and in a method a local does not exist before its first assignment (`user.save` there still calls a `user` reader), while lexical names carry no position.
- Pre-existing, unchanged: `user ||= User.new` is an `operator_assignment`, which the constructor pattern does not bind, so `user.save` after it is unresolved; a declined `@param` tag on that name must not fill the gap (it would type it wrongly), so the edge stays missing.
- Pre-existing, unchanged: `@user = Const.new` in one method binds `@user → Const` on the class even when another method writes something else to it.
- Pre-existing, unchanged: a tag above `private def m(user)` or a `sig`-prefixed def is not attached (`findFollowingMethod` accepts only a `method` / `singleton_method` sibling), so its call is a missing edge; main typed it only when a sibling's same-named tag leaked onto the class.
- A YARD `@return` on an `attr_reader` publishes the accessor's type on the class scope. Since RUBY-03 an untyped sibling PARAMETER with the accessor's name no longer borrows it (`# @return [User]` above `attr_reader :user`, then `def other(user); user.save; end` resolved to `User#save` before). An untyped LOCAL of that name still does (`user = 42; user.save`, the bullet above), which is why the first-statement `findFollowingAttrCall` descent is still not added: it would extend that leak to more classes.

### Future: field typing from typed parameters (parked design, not in this PR)

Inferring `@ivar → T` from `@ivar = param` with `# @param param [T]` was prototyped and withdrawn: per-file capture synthesis cannot see every write to the field, so the published type can be wrong, and a wrong field type reaches every reader of the ivar. Any future attempt must start from this hazard list and decline whenever one applies:

1. Writes the per-file collector cannot classify must veto, not be skipped: writes under a block body (`[..].each { |log| @user = log }`), `@user, x = …` multiple assignment, `@user ||= …` / `@user += …`, any non-parameter, non-`Const.new` value (`nil`, call results).
2. Ownership is the Ruby object, not the syntactic class body: reopened classes (same file or another file) and mixins (`module Storage` included into the class) all write the same ivar, so agreement must be established across every body that can write it — which a per-file capture layer cannot do.
3. Generated writers are writes: `attr_accessor :user` / `attr_writer :user` let `h.user = AuditLog.new` change the field without any `@user =` in the class.
4. `normalizeYardType` turns `Array<User>` into `User`; a container-typed parameter must never publish its element type as the field's scalar type.
5. Parameter rebinding before the ivar write must veto: plain and multiple assignment, `||=`/`+=`, `for x in`, `rescue => x`, block/lambda/nested-def parameters, `case … in` patterns, rightward `expr => x` / `expr in x` (node positions enumerated from the tree-sitter-ruby grammar).
6. Conflicting typed writes (`initialize(user)` `[User]` vs `replace(log)` `[AuditLog]`) must type nothing; agreeing writes must type once; a hand-written reader's own `@return` must win over any inferred accessor type.
7. The accessor name must never be published on the class scope (`user → T`): it is readable from every sibling method's same-named untyped local. Parameters stop the walk since RUBY-03; untyped locals do not.

## Parameters stop the receiver walk (RUBY-03, fixed)

The shared receiver walk stops at the nearest scope that owns the receiver's name, and a scope owns a name it holds no type for only through `Scope.lexicalNames`. Ruby published none, so an untyped parameter was invisible to the walk, which climbed past it and took the type of a same-named binding further out: `user = User.new; items.each { |user| user.save }` resolved the block's `user.save` to `User#save`. `emitRubyScopeCaptures` now attaches `@scope.lexical-names` to every scope that declares parameters, and each binder lands on the scope that declares it:

- a `do … end` / `{ … }` block: its `|…|` names, including destructured, splat, keyword, optional and `&block` parameters and block locals (`|x; user|`); this covers `lambda { |x| }`, `proc { |x| }` and `Proc.new { |x| }`;
- a stabby lambda (`->(x) { }`, `->(x) do … end`, `-> x { }`): its parameter list is a sibling of the body block, so the names are listed on the body, which is the scope;
- a method or singleton method: its parameters, so an untyped parameter no longer borrows a same-named top-level local, a class-level reader type or an enclosing method's YARD tag (a `def` nested in a method).

Blocks retain their existing scopes. Lambda default expressions outside the body get a scope only when they reference a parameter already declared in that lambda. Each scope lists only referenced names, so many defaults do not duplicate every earlier parameter. A block or method that declares nothing carries no capture. Numbered (`_1`) and `it` parameters are not listed: the grammar parses them as plain identifiers, `_1` cannot name an outer local, and `it` reads an outer local of that name when one exists. Locals are not listed (see the boundaries above). A closure that does not bind the name still reads the captured outer local (`items.each { |item| user.save }` keeps `User#save`), and a block parameter reassigned to a constructor inside the block takes that type. A block over a YARD-typed collection (`# @param users [Array<User>]`, `users.each { |u| u.save }`) stays unresolved, as before; `for v in users` keeps its element type. The stopped site records `receiver-type-unresolved` with `declineDetail: untyped-binder` and its binder scope, using the recorder added by DART-11 (#3903). [ruby-block-param-lexical-stop.test.ts](../../gitnexus/test/integration/resolvers/ruby-block-param-lexical-stop.test.ts) pins each shape against exact owner IDs with a decoy `save`, and [ruby-lexical-names.test.ts](../../gitnexus/test/unit/scope-resolution/ruby/ruby-lexical-names.test.ts) pins what each scope lists.

## Bare identifier reads (RUBY-04, fixed)

A receiver-less, paren-less identifier that is a statement of its own is captured as a zero-arity call (`(body_statement (identifier)) @reference.call.free`). Ruby decides that question lexically: the name is a variable read once a formal parameter, a block parameter or an assignment seen earlier in the enclosing scope has bound it, and a method call otherwise. Before the fix `class Host; def target; end; def run(target); target; end; end` produced a wrong `run → Host#target` CALLS edge. `emitRubyScopeCaptures` now drops the capture when the name is bound; [ruby-bare-read-shadows-method.test.ts](../../gitnexus/test/integration/resolvers/ruby-bare-read-shadows-method.test.ts) pins the cases below against the exact `Host#target` ID with a decoy `Other#target`, and [ruby-bare-read-order.test.ts](../../gitnexus/test/unit/scope-resolution/ruby/ruby-bare-read-order.test.ts) pins the helper directly on parsed trees, including shapes the statement pattern never captures.

- Bindings that make the bare name a read (no edge): the enclosing `def` / lambda's formal parameters (positional, optional, keyword, splat, hash-splat, `&block`, destructured), a `|x|` block parameter or `|x; y|` block local of an enclosing block, and a local bound earlier in the same scope by assignment (plain, multiple, `||=`), `for`, `rescue =>`, or a `case … in` / `=>` / `in` pattern (including the hash shorthand `{target:}` and its quoted form `{"target":}`). A block sees the names of every enclosing block and the method; a nested `def` starts a fresh scope and sees none of them.
- Kept as calls: `target()`, `self.target`, `target arg`, a bare name with no binding in scope, a read BEFORE the assignment (`target; target = 1` — Ruby registers a local when the parser passes its assignment), a bare name after a block whose parameter or local had that name (block bindings do not leak), and a nested `def` body reading a name only its enclosing method binds.
- Where a name binds: at the offset where it is WRITTEN, which is the rule Ruby's parser follows. A parameter binds at its name node, so a default expression sees the parameters declared before it and the parameter it belongs to, never a later one: `def run(x = [1].each do |a| target end, target: nil)` calls the method, `def run(target = nil, x = [1].each do |a| target end)` reads the parameter, and `def run(target = [1].each do |a| target end)` reads the nil local (a circular reference); the same holds for block and lambda parameter lists (checked on CRuby 2.6). An assignment target or pattern variable binds at its own identifier, so a read inside the value of a rightward `value => target` / `value in target` or inside an earlier multiple-assignment target's subscript (`arr[[1].map do |x| target end], target = [], 1`) is still a call.
- Header expressions: a singleton method's receiver (`def (target = Object.new).run`), a class's or module's name expression (`class (target = Object)::Inner`), a class's superclass and a `class << value` value are evaluated in the ENCLOSING scope. They bind there, never in the body, so the body's bare `target` keeps its call; a read inside such a header (reachable through a `do` block or lambda body) is answered by the enclosing scope. A bare header name (`class << make_base`) is not a binding site.
- `BEGIN { … }` / `END { … }` bodies share the locals of the scope around them (Ruby's own `BEGIN` / `END` example shares one local with the program): an assignment inside one binds the enclosing scope (`def run; END { target = 1 }; target; end` reads the local), and a read inside one sees the enclosing scope's names. `BEGIN` is valid only at the top level.
- Patterns bind only in binding positions: pattern containers (array, find, hash, alternative, parenthesized) and an identifier, keyword pattern, as-pattern, splat or hash-splat. A string / regex / symbol / subshell `interpolation`, a `lambda` pattern's parameters, a `^pin`, a constant and a range bind nothing, so `in "x#{target}"` keeps the later call. tree-sitter-ruby parses a hash argument whose key starts with a unary operator (`s.put !x => target`, `put :a, -x => target`, `[!x => target]`) as a pattern match under `unary`; inside an argument list, array literal or subscript it is a hash pair and binds nothing, while the statement `!x => target` still binds.
- Not captured either way (pre-existing): a bare name inside a brace block body (`block_body`), a `begin … end` body, an `if` / `case` / `rescue` branch (`then`) or a `for` / `while` body (`do`), which the statement pattern never matched.
- Heredoc bodies are parsed at their opener: Ruby lexes a body when it reaches its `<<~EOS` token, before the rest of that line. The guard links each body to its opener and uses that scope and parse order for both bindings and reads. A body sees earlier parameters and locals, but not an assignment later on the opener line; a read later on that line sees bindings made in the body. The opener's scope still owns the body when a method or block closes on that line: its parameters remain visible, nested method boundaries still apply, and its assignments do not leak into the physical body's surrounding scope. Bodies opened on one line are paired with openers in token order. If their counts disagree, the unmatched body cannot establish a local read or a binding.
- Not guarded (the capture stays, a wrong edge where a same-named method exists, as before the fix): a regex named capture `/(?<target>…)/ =~ s`, `binding.local_variable_set`, `eval`, and the implicit block parameters `it` and `_1` … `_9` in a block without explicit parameters.
- Pre-existing, unchanged: an explicit `target()` beside a same-named parameter resolves to nothing (`RUBY_CALLABLE_CAPTURE_OPTIONS` models `param()` as an invoke through the parameter cell), so that edge is still missing; this fix only removes the wrong edge of the bare read.
- With RUBY-03's parameter lexical names, a bare name that the positional read check proves is a call can still collide with a later parameter or an outer method's parameter. Inside a class/module method, capture routes that call through the existing `self` binding. This preserves calls in nested methods, parameter defaults and heredoc bodies without letting a local read become a call or changing the explicit-call gaps above.
- Performance: each scope's earliest bindings are cached by node id for the file's capture pass. Files with heredocs also build a parse-order index once; ordinary files use source offsets. A read then costs one binding lookup per enclosing scope. Parameter names used to detect an implicit-self collision are also cached per scope. These caches expire with the capture pass.
- Follow-up: the RUBY-01 rebinding guard (`rubyParameterNames` / `lhsBinds` / `patternBinds`) walks the same binding positions with its own helpers. Folding it onto these collectors is not mechanical: its pattern walker errs toward declining on unknown pattern kinds (a missing edge is its safe side), while this collector errs toward keeping the call, so the merge would change RUBY-01's decline set and needs its own pins.
