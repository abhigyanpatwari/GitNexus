# R Ingestion Gaps

Audited on 2026-10-24 with freshly built production sources at `a9b112ae5` and the
accompanying receiver corpus and regression tests. See the [measurement audit](receiver-resolution-audit.md)
for the benchmark commands, target checks, exclusions and test limits. R has no row in
the receiver shape arm of that benchmark (no `bench/receiver-resolution` entry was added, as for
Zig and Objective-C), so every state below comes from the dedicated corpus and
regression tests named in each item, not from `baseline.json`. Broader ingestion is not
exhaustively assessed. The supported behaviour is described in the [R provider guide](r-provider.md).

## Receiver shape snapshot

States below come from the [receiver corpus test](../../gitnexus/test/integration/resolvers/r-receiver-corpus.test.ts),
a table of call shapes, each with a caller, an exact expected target (or no edge) and the
outcome recorded at the call. Its fixtures are `r-receiver-corpus/` (no `DESCRIPTION`, so
the unique-name fallback is live; R6 `User` and `Address` both define `save`, and free
functions `save`, `greet`, `climb_up` and `nothere` are the decoys) and
`r-receiver-corpus-qualified/` (a package that re-exports another package's `fmt`, and a
caller-local `fmt` as the decoy). A row that resolves asserts the exact node id (for
example `Method:R/models.R:User.save#0`) and that no other edge leaves the caller; a row without
an edge asserts that the caller has no edge at all (so also none to a decoy) and
names the positive control that resolves nearby. Two repository-wide checks add that no edge
reaches a decoy and that the table lists every edge and every dropped site.

In the harness vocabulary of the [README](README.md#reading-the-evidence):

- **RESOLVES** (exact target, no decoy edge): a receiver typed by a constructor in the same
  function (`u <- User$new(); u$save()`), including when `Address` shares the method
  name `save` with `User` and with a free function; typed siblings in either order; `self$m()`
  inside an R6 method for an own method and for one inherited from a parent (the corpus has the
  parent in the same file; `r-self-binding` covers another file), also after a write through
  `self` (`self$visits <- 1`), and for a parent's public method when the class has a private
  one of that name (`self` is the public interface); `pkg::fmt()` for a package that defines the function, and for a package that re-exports it from a
  second package (one hop), each beside a caller-local `fmt`.
- **VISIBLE-GAP, a recorded drop** (no edge, with an outcome that counts toward the `impact`
  lower bound): `self$m()` where neither the class nor a parent defines `m` as a public member,
  a private method included (`self$secret()`; `member-lookup-ambiguous`, the shared pass's
  closest label), `self$m()` in a free function
  (`receiver-owned-but-unbound`), and a chain with a variable at its base: `a$b$save()`,
  `User$new()$save()`, `self$repo$save()` (`receiver-unresolved`). These are
  deliberately unresolved: a decoy edge would be wrong, and the right answer needs types that
  R6 does not declare (R-21).
- **INVISIBLE-GAP** (no edge and no recorded outcome, so drop counts cannot reveal it): an
  untyped local (`u <- make_user(); u$save()`), an untyped parameter, an untyped sibling of a
  typed function that reuses the parameter name (the typed function does not lend its type, in
  either order), a roxygen-typed parameter (`#' @param repo User`, `User` a class of the same
  file), the S4 spelling `u <- new("User")`, `super$greet()`, `private$secret()`, a RefClass
  method calling a sibling by bare name, calls of an S4 generic, generator or `new("Pt")`, and
  chains whose base is not a variable (`get_user()$save()`, `pkg::User$new()$save()`,
  `x[[1]]$f$save()`). The untyped controls are intended to stay unresolved; the rest are
  shapes a later slice could resolve (R-18 to R-21, R-23) or that mint no site today (R-06).
  A RefClass `.self$m()` call is a recorded drop (`receiver-unresolved`), and a bare call
  of a name that is both a RefClass method and a free function is ambiguous: no edge to either.
- Qualified sites that are dropped (`ext::fmt()` for a certainly external package,
  `invisiblepkg::fmt()` when package discovery was truncated) get no edge, never the
  caller-local `fmt`, and record no outcome (R-04).

Of 49 corpus cells, 13 resolve, 17 are deliberately unresolved and 19 are `deferred` rows
(absence pinned so that a later feature shows up as a deliberate change); every row
without an edge names a resolving control. Nothing in the corpus reaches a decoy.
