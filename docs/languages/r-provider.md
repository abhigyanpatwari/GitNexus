# R Language Provider

Status: implemented (experimental)

The provider is covered by unit and integration tests, listed under [Tests](#tests). It is classified as experimental in the language support table. This status describes what is implemented today; it does not promise R's dynamic dispatch.

Wrong or lost results inside the supported slice, and the work that is deliberately deferred, are tracked with IDs (`R-NN`), evidence labels and pinning tests in [r-ingestion-gaps.md](r-ingestion-gaps.md). This guide describes the behaviour; that inventory is the starting point for a plan.

## Scope

GitNexus indexes `.r` and `.R` files with the `@eagleoutice/tree-sitter-r` grammar and resolves them through the scope-resolution pipeline (see ARCHITECTURE.md, Scope-Resolution Pipeline). R-specific logic lives in `gitnexus/src/core/ingestion/languages/r/`, with the per-language extractor files beside those of the other languages (the import resolver is `languages/r/import-target.ts`). Apart from the registrations every language has (the language enum, the file-extension and classification tables, the grammar loader and parse-worker grammar map, and the query, provider and scope-resolver registries), shared ingestion code does not name R; the provider plugs in through `LanguageProvider` and `ScopeResolver` hooks. The grammar is loaded through the shared grammar loader on first use, and the parse worker loads it behind a guard like the vendored grammars: if the native binding cannot load, R files are skipped with one logged warning per run and no other language is affected (the warning names the file count and either "parsing disabled via GITNEXUS_SKIP_OPTIONAL_GRAMMARS" when the grammar was opted out, or "parser not available (native binding may not have built)" with an `npm rebuild @eagleoutice/tree-sitter-r` hint). R's own warnings are the package-configuration ones in `package-config.ts`.

R has no class syntax: classes are function calls (`R6Class(...)`, `setClass(...)`, `setRefClass(...)`) and package exports live in a NAMESPACE file rather than in the source. That is why the provider uses three optional hooks: `postParse` (attach each member to its owner and refine export status once every file is parsed), `resolveMemberOwnerNode` (find the owner of a member from a call rather than an enclosing node) and `resolveDetachedOwnerName` (qualify a member's id with its class, so two classes in one file that share a member name stay distinct nodes: `Method:R/a.R:Stack.push#0`, `Property:R/a.R:Stack.items`).

## Supported constructs

Definitions:

- Functions defined by assignment (`<-`, `=`, `<<-`). S3 methods appear as ordinary functions with dotted names such as `print.foo`.
- S4 classes (`setClass`), generics (`setGeneric`), methods (`setMethod`) and slots (`representation`, `slots`).
- A `setMethod()` is owned by the class its signature names: the string, or the first argument of `signature(...)` or `c(...)`. A method on several classes (multiple dispatch) belongs to its first class, so `signature("A", "B")` and `signature("A", "C")` give one method of `A` (the first written wins) and a signature whose first argument is not a string names no owner.
- R6 classes with their methods, fields and active bindings.
- RefClass (`setRefClass`) classes with their methods and fields.
- Slots and fields given as `list(...)`, `representation(...)` or `c(...)`. A named entry (`c(a = "numeric")`) records its type; an unnamed string in `slots = c("a", "b")` or `fields = c("a", "b")` names an untyped member, as in R. An unnamed string in `representation(...)` or `list(...)` is not a member.
- The argument that names an S4 or RefClass class, a generic or a method is the argument spelled with the first formal (`Class=`, `name=`, `f=`) wherever it sits, else the first unnamed argument (so a later `Class=` takes the formal from an earlier unnamed argument, as in R). Other strings (`contains=`, `valueClass=`, a `setMethod` signature) create no node.

Types:

- `x <- Type$new()` (R6, RefClass) and `x <- new("Class")` (S4) type `x`. Resolution of `x$method()` is asserted by tests for R6 only (`r-receiver-corpus`). The S4 `new()` binding is made in the per-file type environment, not in the scope, so it types no receiver (`u <- new("User"); u$save()` has no edge); it is unit-tested only. A constructor types a name only when every binding of that name in its frame agrees with it (`receiver-agreement.ts`): a second class, an untyped value, a loop variable, a formal, `rm(x)`, `assign("x", ...)` or `class(x) <- v` in the same frame leaves the receiver untyped, and `obj$m()` then ends as `receiver-unresolved` with no edge, never as an edge to another class's method. `NULL`, a constant and a write through the object (`x$a <- v`, `x[[i]] <- v`) do not count against it. A frame is the file's top level or one `function_definition`; the braces of `local({...})` and of other calls belong to the enclosing frame; `<<-` and `->>` bind in no frame of their own but are recorded in every enclosing frame, up to the top level. A module-level `u <- User$new()` also types `u` in the file's functions, unless a function binds `u` itself or the file `<<-`s it. Frames are per file: a package namespace spans files, so a rebinding in another file is not seen (R-36). `with()` and `within()` are not modelled (R-35). A test file that reuses one name for different classes in several `test_that` blocks leaves that name untyped in all of them, because blocks are not frames. A local from any other call, a parameter and a roxygen type leave it untyped (see [r-ingestion-gaps.md](r-ingestion-gaps.md), R-20).
- roxygen2 `@param` types in a restricted form: the description is the type alone (`#' @param name Type`) or starts with it in braces (`#' @param name {Type} prose`), the type is an R6, S4 or RefClass class defined in the same file, and the name is a formal of the function the block documents. The type is bound inside that function only. Prose that begins with a capitalised word binds nothing. Other roxygen2 tags (`@return`, `@field`, `@inheritParams`, `@rdname`, `@noRd`, `@export`) are not read.

Imports:

- `library()` and `require()` resolve to local packages, and `source()` to local files. The argument is `package=` / `file=` wherever it sits, else the first unnamed argument after any named one; named-first arguments such as `lib.loc=` and `local=` are not imports.
- NAMESPACE `importFrom()` names bind to definitions in local packages. A name that can never bind (not exported, not defined at top level, or dotted) creates no import, so its calls keep the `global-name-fallback` guess, unless the name is provably private to its package: then the guess is vetoed too and the call gets no edge (see Export status).

Calls:

- Free calls, `obj$method()` calls (receiver typed as above), R6 `self$method()` calls, and calls inside native pipe (`|>`) chains.
- A chained member call, `a$b$m()`, `Cls$new()$m()` or `self$f$m()` (the receiver is itself a `$`/`@` access or a call), is never typed: R6 fields and method results carry no declared type, so the chain is not followed. The site is minted with the shared codec's `truncated` receiver chain, which the shared fold refuses, and the call ends with a `receiver-unresolved` outcome and no edge, instead of reaching a free function or a method of that name elsewhere (it counts toward the `impact` lower bound). The first link must be a plain variable: a chain based on a call (`get_user()$save()`, `pkg::Cls$new()$m()`), on `x[[1]]`, `x[1]` or `(x)`, or one the codec cannot encode (more steps than its depth limit, a name with a space) mints no site at all: no edge and no outcome. That shape is invisible, not unresolved. The shared fold's comment calls the `truncated` marker defence in depth that no producer mints; R relies on it: `r-receiver-chain.test.ts` fails if R stops minting the marker or if upstream starts folding a truncated chain. End to end the marker is not load-bearing today: with it removed (`truncated: false`), the outcomes and edges of the `r-chained-receivers` fixture are unchanged and only that unit test fails (R-09). Renaming a function whose name is the last step of such a call (a free `save` beside `a$b$save()`) is refused as `ambiguous_reference`.
- A replacement-function call, `foo(x) <- value`, is recorded as a call of `` `foo<-` ``, as R runs it (`=`, `<<-`, `->` and `->>` too, and `pkg::foo(x) <- v` as a call of ``pkg::`foo<-` ``, which passes the export check of the setter name: a NAMESPACE entry may be written ``export(`foo<-`)`` or `export("foo<-")`, and an unexported setter is dropped from outside the package, never replaced by the getter). A call is in a replacement position when it lies in the target chain, reached only through first arguments and the bases of `$`, `@`, `[` and `[[`; every call of the chain is recorded as its own setter (`foo(bar(x)) <- 1` calls `` `foo<-` `` and `` `bar<-` ``), so the getter half that R also evaluates (`bar(x)`) has no edge: a missing edge, not a wrong one. Other arguments (`foo(x, bar(1)) <- v`, the index of `foo(x)[bar(1)] <- v`) and the assigned value stay ordinary calls, and `x$a <- 1` or `x[i] <- 1` (a builtin setter) has no call site at all. A function defined as `` `foo<-` <- function(x, value) ... `` is now found by the call; a string-spelled definition (`"foo<-" <- function(...)`) and `setReplaceMethod()` / `setGeneric("foo<-")` define no node, so such a call has no edge (not even to the getter). An explicit `` `foo<-`(x, v) `` is unchanged. `rename` refuses both halves of a replacement pair (see Rename).
- `self` in an R6 method is typed as the class: `self$m()` resolves through the class and its parents (`inherit =`) at the receiver-call confidence (0.85), never to a free function of that name. The class is the name the `R6Class` call is assigned to (`Child <- R6::R6Class(...)`, bare or `R6::`), and the method is a function in its `public`, `private` or `active` list (a private method has a typed `self` too). `self` is the public interface, so `self$m()` reaches only public and active members: a method in a `private` list, of the class or a parent, is skipped, and a parent's public method of that name is the target even when the class has a private one (`private$m()` itself is not resolved). A closure inside a method sees the method's `self`. Writing through `self` (`self$count <- 1`, `self[["x"]] <- v`, `self$items[[i]] <- v`, `names(self$items) <- v`) leaves it the instance. Where `self` is no R6 instance (a free function, a parameter called `self`, a plain `self <- other()` in the method or function, an `R6Class` call that is assigned to nothing, a `setRefClass` method) a `self$m()` call gets no edge and the resolution outcome is `receiver-owned-but-unbound`, unless that binding is itself typed (`self <- Foo$new()` makes `self` a `Foo`); a method that neither the class nor a parent defines as a public member (or a parent that is not indexed, as in `inherit = pkg::Base`) gets no edge and the outcome `member-lookup-ambiguous` (the closest label the shared pass offers for "member not found"). A file that binds `self` itself (`self <- Foo$new()` at top level) is exempt: its free functions read that object. The same lookup rules hold for every typed receiver, not only `self`: `u <- User$new(); u$secret()` does not reach a private method (a typed miss records `member-lookup-ambiguous`), `u@save()` is not a member call and makes no site, and a call through a generator object (`g <- setRefClass(...)`) is not a receiver. A class whose name contains a dot (`My.Class`) gets no receiver lookup at all, for `self$m()` and for typed receivers alike: the call ends `receiver-unresolved` with no edge, where it used to reach a same-named free function (R-13). The edge of a `self$m()` call is labelled `global` at 0.85 when the class is in the caller's file and `import-resolved` at 0.85 when it is in another file.
- A call through a name that a function's formal or one of its `for` variables binds (`function(data, transform) transform(data)`) gets no edge, not even to a top-level function of that name. The scope publishes those names as lexical names: they stop the lookup and the unique-name fallback. Every named formal is a lexical name, whatever its default: a default (`n = 2`, `helper = NULL`) proves nothing about the argument a caller passes, which may be a function, so a call through the formal is never bound to a function of that name outside. A `for` loop outside every function binds nothing.
- An ordinary assignment in a function's own body is a lexical name too, when its value may be a function (`helper <- identity`, `helper = some_fn()`, `identity -> helper`): a call of the name in that function, or in a closure nested in it, gets no edge to a top-level function of the same name. A function literal (`helper <- function(y) 2`) is a real definition and the call resolves to it; a constant (`helper <- 2`, a string, `TRUE`) is skipped by R at a call, so the call still reaches the outer function; `<<-` and `->>` assign outward and bind nothing in the frame. A complex target binds its base (`names(x) <- v`, `x$a <- v` bind `x`, never the called name). The rule is flow-insensitive, a deliberate trade for a conservative result: a call written before the assignment, or under an `if` that may skip it, is left unresolved too. Not modelled, so the call still reaches the outer function: `assign()`, `delayedAssign()`, `list2env()` and `with(list(...), ...)` values (R-02; pinned by `r-assignment-locals`), and a string target (`"helper" <- identity`). The braces of `local({ ... })` are read as part of the function body, so an assignment inside them makes the name lexical (the call gets no edge). Braces that R evaluates in an environment of their own (`local({...})`, `with(data, {...})`, `within()`, testthat's `test_that(desc, {...})`, `describe()` and `it()`, bare or `pkg::`-qualified) are block scopes: a function literal defined inside is visible in those braces only, so a call from another block or file does not reach it (`fallback-refused`, never the 0.5 guess). `withr::with_*()` and `suppressWarnings({...})` evaluate their braces in the caller's frame and get no scope. A block-local definition still counts toward the uniqueness of its name, so a call elsewhere of a name that is also defined at top level in another file gets no edge where R would call the top-level definition: a lost edge, not a wrong one (R-40). Module-level assignments are not modelled either: a top-level `helper <- identity` (or `helper <- 5`) in the caller's own file still lets the unique-name fallback reach another file's `helper` at 0.5. A qualified call is decided by its qualifier alone: `function(f) mypkg::f()` and `helper <- identity; pkga::helper(x)` still bind `mypkg`'s `f` and `pkga`'s `helper` (the shared free-call pass resolves the qualifier before it applies a lexical name claim).
- Named nested functions (closures) are indexed, and calls inside attribute to the nested function, which can shadow a top-level name; a nested function reads the lexical names of the function around it. Top-level script calls outside any function are attributed to the File node.
- `pkg::fn()` and `pkg:::fn()`, decided by the qualifier (see [Resolution model](#resolution-model)).

Heritage:

- R6 `inherit=` and S4 `contains=` (a single class or `c(...)`). `contains = "VIRTUAL"` links to one placeholder class named `VIRTUAL`.

Exports:

- Read from each local package's NAMESPACE: `export()`, `exportClasses()`, `exportMethods()`, `S3method()` and `exportPattern()`. `S3method(generic, class, method)` registers `method`, the function R registers, else `generic.class` (a generic of another package, `S3method(pkg::generic, class)`, registers `generic.class`). A registration is not an export: `pkg::generic.class`, `library(pkg)` and `importFrom(pkg, generic.class)` do not reach a method that only `S3method()` names, though a function also named by `export()` or `exportPattern()` is still exported. The graph node of a registered method stays public (`isExported`), and `rename` refuses it. Conditional (`if`/`else`) exports, raw-string and multi-line arguments and the text after a malformed directive are not read (see Limits and known gaps). A `DESCRIPTION` file with a `Package:` line marks a package root.

## Resolution model

The scope query (`languages/r/query.ts`) captures four call shapes only: `f(x)`, `pkg::f(x)`, `obj$f(x)` and a chained `a$b$f(x)` (an `extract_operator` or a call as the receiver; see the chained-call bullet under Calls). A free or qualified call in the target of an assignment (`f(x) <- v`) is a call of the setter `` `f<-` `` (see the replacement-function bullet under Calls).

- A bare call binds lexically first. `library()` and `require()` of a local package attach that package's exports, as R does for an installed package: every top-level name when the package has no NAMESPACE file, otherwise the names the NAMESPACE provably exports (`export()`, `exportClasses()`, `exportMethods()`, a matching `exportPattern()`; `S3method()` registers a method and does not export it). A name the NAMESPACE does not export is not attached, and neither is a name it may export but cannot be proven to (an unreadable NAMESPACE, or an `exportPattern()` that was dropped or cut short by its work budget): the 0.85 edge a `library()` yields needs proof. The hook has no importer, so a `library(ownpkg)` issued from inside the package (its `tests/` included) attaches only the exports too. When two attached packages define the same name, the package attached last wins, as R masks it: of the `library()` calls whose package defines the name, the one that comes last in the file decides (calls inside a function are not told apart from top-level ones, and a package named by several calls counts at the first of them, because R leaves an attached package where it is: `library(a); library(b); library(a)` still lets `b` mask `a`). Two files of that one package that both define the name stay ambiguous, with no edge. This differs from `devtools::load_all()`, which attaches every top-level name; the earlier behaviour of this provider followed `load_all()`. `source()` binds no name; a call into a sourced file, or into another file of the same package, binds through a workspace-wide unique-name fallback at confidence 0.5 (`global-name-fallback`). That guess skips a candidate its package's readable, complete NAMESPACE does not export, unless the caller sits inside that package's directory tree (see Export status); a name that is not provably private (unreadable NAMESPACE, a cut-short `exportPattern()`) keeps the guess. An ambiguous name yields no edge, and a function defined inside another function, or inside a block scope (see Calls), is never a candidate (no other function can reach it by name). In package code the guess is also bounded by the package's declared dependencies. When the caller is in `P/R/`, P has a NAMESPACE and neither its exports nor its imports were unreadable: Rule A vetoes a candidate in another repository package Q unless P has an `importFrom` entry for the name, imports Q (`import(Q)`, `importClassesFrom(Q, ...)` or `importMethodsFrom(Q, ...)`), lists Q in `Depends:` (transitively, since `library(A)` also attaches A's `Depends:`), or the caller file has a `library(Q)` / `require(Q)`; Rule B vetoes a candidate that is in no package's `R/` (a loose script, another tree's `tests/` or `inst/`) unless an `importFrom` entry exists; Rule D vetoes a call from `P/tests/` to a definition under `P/data-raw/` or `P/inst/`, which tests reach only by sourcing them, unless the caller file calls `source()`, `system.file()` or `test_path()`. Rules A and B veto calls that are unsupported for check-clean package code: the package's declared dependencies cannot justify them. That is stricter than the shared hook's wording ("impossible"), since a user can attach Q by hand and the call then runs; the provider prefers an unresolved call to an edge into a package the code does not declare. A vetoed guess records `fallback-refused`. Scripts are not constrained by these rules (R-34).
- A bare call never binds to a dotted definition, so `foo(x)` cannot reach `print.foo`. Dotted (S3-style) names are never import-resolved and skip the 0.5 fallback; a call that spells the full dotted name (`read.config(x)`, `print.foo(x)`) binds by qualified-name lookup at confidence 0.35 (`scope-resolution: call`) to a unique definition, in the same package or another file, whether or not a `library()` attached it. That lookup also matches a member whose qualified name is `Class.member`, so `data.frame(x)` can bind the method `frame` of an R6 class `data`, and `Stack.push(x)` a member `Stack.push`: a wrong edge when the call means a base-R function or a function from another package (R-32). Dotted names are not bound through `importFrom()`.
- `pkg::name()` is decided by its qualifier:
  - `pkg` is a package of the repository and defines `name` exactly once: the call binds to that definition at confidence 0.85 (`import-resolved`), subject to the export rule below.
  - `pkg` is certainly not a repository package (discovery completed and found no such package, including a repository with no `DESCRIPTION`): no edge.
  - `pkg` defines `name` more than once: no edge.
  - `pkg` is a repository package that defines no `name`: the call binds only when `pkg` re-exports it, i.e. its NAMESPACE has `export(name)` and `importFrom(origin, name)` for a repository package `origin` that defines `name` exactly once (one hop; the last `importFrom` of the name wins). The edge goes to `origin`'s definition at 0.85. Anything else (not exported, no `importFrom`, an external or multiply-defining origin, `:::`) gives no edge: a same-file or other-package definition of that name is never reached through a qualifier.
  - Discovery may have missed a package (its limits were reached): the call gets no edge. No qualified call is left to the lexical or name-guess tiers.
- `::` and `:::` differ. `pkg:::name` binds to the definition whether or not the package exports it. `pkg::name` binds only when the package has no NAMESPACE file or exports the name, or when the caller sits inside the package's directory tree (see Export status); a `::` to a private name (or one not provably exported) from outside gets no edge, as R errors there.
- Package discovery is bounded to depth 3 and 200 directories (when the bound may have hidden a package this is flagged internally and nothing is logged), reads directories in code-unit order, ranks duplicate package names by shallowest then by whole path, and never searches the directories the indexer itself ignores (dot-directories, `vendor`, `build`, `dist`, `lib64`, `fixtures` and the rest of its built-in list) or those named exactly `renv`, `packrat`, `revdep` or `<name>.Rcheck`. A `DESCRIPTION` with a `Built:` field is an installed library package (`lib/`, `library/`) and registers nothing. `DESCRIPTION` and `NAMESPACE` are read only as regular files (a symlink is not followed) and only up to 4 MiB; a larger `DESCRIPTION` leaves its package undiscovered (discovery counts as incomplete) and a larger `NAMESPACE`, or one that is a symlink, is treated as absent. The shared file scanner has no `renv`, `packrat`, `revdep` or `.Rcheck` entries, so `.R` files inside those trees are still parsed even though discovery skips them.
- Export status: the language-level export check treats every symbol as public. The NAMESPACE pass then marks the remaining `R/` symbols of a NAMESPACE-bearing package non-exported. Symbols outside `R/` (`tests/`, `vignettes/`, `inst/`) are not package members and stay public; files in `R/` subdirectories are treated as `R/` files although R itself does not load them. A package without a NAMESPACE stays fully public, and a nested package without one does not inherit its enclosing package's. roxygen2 `@export` tags are not consulted by the index (`rename` does read them, see Rename). The refinement changes the graph nodes' `isExported` only; the definitions scope resolution works from carry no export verdict (`isExported` stays undefined there, since a `false` would drop the name from wildcard providers). Resolution instead computes a visibility per top-level name from the same NAMESPACE reading, once per pass: `public` (the package has no NAMESPACE file, or exports the name), `private` (a readable, complete NAMESPACE does not export it) or `unknown` (not exported, but the NAMESPACE is unreadable or an `exportPattern()` was dropped or cut short). `library()` and `pkg::name` need `public` (strict); the global-name fallback vetoes `private`, and, for package code, the dependency rules A, B and D (see Resolution model), but not `unknown`. The inputs are tested in sorted order and completeness is read after the whole batch, so a work-budget cutoff gives the same verdicts whatever the order of files or call sites. A caller is inside package P when the longest package directory (a package with a `DESCRIPTION` or a NAMESPACE) that is a path prefix of its file is P's: `tests/`, `inst/` and `vignettes/` of P count as inside, a nested package claims its own files, and for a root-level package every file outside a nested package counts as inside (so the private-name exemption is broad there). Callers inside P reach P's private names through `pkg::name` and the name guess.
- `exportPattern()` text comes from the analysed repository, so patterns are compiled to a linear-time automaton (`linear-regex.ts`) with a work budget. Constructs with no linear-time algorithm (back-references, look-around), constructs TRE reads differently from JavaScript (`\<` `\>`, `\a`, `\e`, `\Q`, `\E`, `\x{`, `\u`, any backslash inside `[...]` (TRE reads it as a literal member, so `[a\-z]` is a range from `\` to `z` and `[\n]` holds `n`; this drops the common `exportPattern("^[^\\.]")`, whose names then read as not provably exported; write `"^[^.]"`), `[.x.]` and `[=x=]`, `{,n}`, a leading `]` in a bracket expression that has no POSIX class) and oversized patterns are dropped with one logged warning per pattern per package, and `rename` then reports `incomplete_semantics`. Character classes use ASCII semantics. A directive argument the NAMESPACE reader cannot read at all is dropped without a warning: an R 4.0 raw string (`exportPattern(r"(^[^.])")`, `export(r"(foo)")`) and any string that spans lines. It exports nothing, so the names it was meant to cover read as non-exported in the index. The reader records that it dropped something that may hide an export (this, a conditional `export()` below, or a malformed directive that swallowed one), and `rename` refuses on that record (see Rename).

## Limits and known gaps

Not edges or nodes:

- A function passed as a value (`lapply(x, f)`, `Map`, `lapply(x, pkg::f)`), dynamic calls (`do.call("f", ...)`, `match.fun()`, `get()`) and dispatch through a registry (`handlers[["a"]]()`) create no CALLS edge, because only the four call shapes above are captured; the cross-language callable-value analysis classifies R as not applicable.
- R6 `super$method()` and `private$method()` calls (nothing binds `super` or `private` to a class), S4 slot access (`obj@slot`), and `UseMethod()` / `NextMethod()` create no edge.
- Anonymous functions (`function(x)`, `\(x)`) passed as arguments are not indexed as definitions; calls inside are attributed to the enclosing function, or to the File at top level.
- Infix operators (`a %op% b`) are not linked to their definitions.
- Constants and other top-level non-function assignments, and environments (`new.env()`, `local()`, `assign()` / `get()`), are not nodes; the only value-like nodes are R6, RefClass and S4 fields and slots. `setValidity()`, `setClassUnion()`, `setReplaceMethod()` and `Class$methods(...)` create no definition or edge.
- No framework or entry-point detection (Shiny, plumber, targets, testthat). Plumber `#*` annotations are not read and no route nodes are created, and no route or fetch edges link R to other languages.

Known gaps in call resolution and class handling. Those that decide which target a call reaches are tracked with IDs, evidence and pinning tests in [r-ingestion-gaps.md](r-ingestion-gaps.md): the dotted R6 class name (R-13), a global `self` bound in another file (R-14), RefClass calls by bare name and through `.self$` (R-19), and the S4 generic, generator, `new()` and `Class$new()` calls that get no edge (R-18). Rows R-26 to R-42 record the boundaries found while fixing the audit. The rest were reproduced and are left as is:

- `source()` paths are matched by suffix: leading directories that do not exist are dropped until a file matches, so `source("secrets/config.R")` binds `R/config.R`, and the first of several matches wins. Backslash paths and absolute paths resolve to nothing.
- `library(localpkg)` creates one `IMPORTS` edge per file of the package from every importing file, so 100 scripts and a package of 200 files give 20,000 edges.
- When two repository packages each define a helper of the same name, a bare call to it from another file of either package gets no edge: the name is ambiguous in the repository, although the caller's package decides it in R.
- `METHOD_OVERRIDES` compares parameter counts, so an R6 or RefClass method that overrides one with a different formals list (`speak = function(loud = TRUE)` over `speak = function()`) gets no edge, although R has no overloading.
- Calls inside the function of a `setMethod()`, `setGeneric()` or `setValidity()` call are credited to the File, not to the `Method` node the same call creates. Calls inside `validity =` of `setClass()` are credited to the Class.
- R6 `inherit = pkg::Base` and legacy S4 `representation("Base")` create no `EXTENDS` edge.
- R6 members named by a string (`"c d" = function() ...`, `'e' = 3`) are dropped; backticked names are kept with their backticks. A class or owner name read from a string keeps its escapes undecoded, so `setClass("Hello\x41")` is a different class from `setClass("HelloA")`, which R treats as one.
- A function nested in an R6, RefClass or `setMethod()` body has an id such as `Counter.function.bump@7:21`: the enclosing function's name is a placeholder and the line and column keep ids apart, so ids change when lines shift.
- A base class named by `inherit =` or `contains =` that is defined more than once in the repository (in two files, or twice in one) gets no `EXTENDS` edge from a class in another file; a base defined in the deriving class's own file is found.
- Export patterns use JavaScript regular-expression syntax where R uses TRE. The constructs where the two differ are refused, not guessed (see the NAMESPACE bullet above), including every backslash inside `[...]`: `exportPattern("^[^\\.]")` is dropped although TRE and JavaScript disagree on it only for names that contain a backslash, because `[a\-z]`, `[\n]` and `[\]]` differ for ordinary names and no narrower rule has been checked against R.
- NAMESPACE `if (...)` and `else` bodies are skipped, so a function exported only conditionally (`if (getRversion() >= "4.1.0") export(new)`) reads as not exported in the index. So does anything after a malformed directive up to the next line that starts with `name(` in column 0. Skipping a body or a malformed directive that names an export-family directive (`export`, `exportClasses`, `exportMethods`, `S3method`, `exportPattern`) is recorded, and `rename` refuses a function of such a package; the persisted `isExported` is not changed by it.

A class name that is not unique: a member attaches to the class of its own file when several classes share the name (the same helper class in `R/` and `tests/`, a class defined twice in one file counts once). When the member's file defines none of them, or several, the member stays unowned with its `ownerNameHint`, and one warning for methods and one for fields name the class names concerned (at most five each).

Not supported:

- The magrittr pipe `%>%` has no specific support and none is claimed; the native pipe `|>` is supported. tidyverse non-standard evaluation (bare column names, `.data$x`) is not modelled.
- `.Rmd` and `.qmd` files are not indexed (the provider handles `.r` and `.R` only; `.Rprofile` and `.Renviron` are not indexed either), and `box::use()`, `import::from()`, `loadNamespace()`, `attachNamespace()` and `sys.source()` imports are not read.
- S3 dispatch is not resolved: S3 methods are indexed as functions only. S4 and RefClass dispatch is not resolved either; there are definitions and heritage, not dispatch edges.
- NAMESPACE `import()`, `importClassesFrom()` and `importMethodsFrom()` create no import edge and bind no name. They are read only as a declared link to a repository package (the dependency rules A and B in Resolution model), and `DESCRIPTION` `Depends:` likewise. Imports of external (CRAN) packages produce no edges.
- NAMESPACE `exportClassPattern()` is not read. An S4 class exported only through such a pattern reads as not exported (`isExported` false), and an `importFrom()` of it does not bind; classes listed in `export()` or `exportClasses()` are read.
- S4 `contains=` links only to classes defined in the repository or the `VIRTUAL` marker; basic-type bases such as `"numeric"` add no edge.
- Package discovery is bounded (depth 3, 200 directories), so a package beyond the bound is treated like an unknown one. A package found only under `renv`, `packrat`, `revdep`, `<name>.Rcheck`, a dot-directory or another directory the indexer ignores, or whose `DESCRIPTION` has a `Built:` field, is not a repository package.
- A `pkg::name` whose package defines no `name` resolves only through a one-hop re-export (`export` plus `importFrom` of a repository package); a re-export through a second hop, through `exportPattern()` only, or through `import()` gets no edge. `pkg::name` used as a value is not qualifier-resolved. Call sites dropped for certainly-external, unknown-locality, duplicate-definition or not-exported qualifiers leave no recorded outcome, because the drop runs before outcomes exist (R-04, R-11).
- When discovery may have missed a package, a `pkg::name` call gets no edge (it used to keep the name-based guess). A `library(pkg)` attaches no private or not-provably-exported name, and a bare call of a name whose NAMESPACE is unreadable or whose `exportPattern()` was cut short (`unknown`) still gets the 0.5 guess, because it is not proven private. A `library(ownpkg)` from inside the package loses the private names at the 0.85 tier too (they fall to the 0.5 guess, which is allowed for callers inside the package). A `source()` of a private package file does not reach its names through the guess: the guess is vetoed for callers outside the package tree, although R puts sourced names in the global environment. A class reached as a receiver type through a `library()` IMPORTS edge (`ResultSet$new()` then `rs$count()`) is not filtered by this rule (R-03, R-07, R-08, R-12).
- Files in `R/` subdirectories are treated as package-owned, although R itself does not load them.
- NAMESPACE is read from disk during analysis, but neither it nor `DESCRIPTION` is a parsed source file. After an edit to either alone, an incremental analyse (no `--force`) keeps stale manifest-derived data: the persisted `isExported` of symbols in unchanged `R/` files, a `CALLS` edge bound through an `importFrom()` whose target changed, a `pkg::fn` edge after a `Package:` rename, and a `library()`, `pkg::fn` or name-guess edge whose target's export status changed. A full analyse is correct and `analyze --force` recomputes it. This is a limitation of the shared incremental write path (only changed files are re-processed), not of R resolution; other language manifests that feed resolution can be affected in the same way. A stale `isExported` does not reach `rename`: the rename guard does not take the persisted flag as proof that a function is private, and reads the package's NAMESPACE again at plan time (see Rename).
- A name written in backticks (`` `%+%` ``, `` `my fn` ``) keeps its backticks on the node, and a definition and its call resolve only when both spell the name alike: `` `helper`(x) `` against `helper <- function(...)` (or the reverse) gets no `CALLS` edge. NAMESPACE `export()`, `exportPattern()`, `importFrom()`, `pkg::name()` and `rename` match the symbol whichever way it is written. `importFrom(pkg, `%||%`)` binds a call spelled like the definition (`` `%||%`(x, y) ``), and a call spelled the other way gets the name-based guess instead.
- Roxygen `@param` types live in the per-file type environment; no graph edge consumes them.
- Argument matching follows R for named and reordered arguments but does not model partial argument names: `setClass(Cla = "D")`, `new(Cla = "E")`, `setRefClass(Cla = "A")` and `setMethod("show", sig = "Foo")` are not recognised, so no definition or owner is attached.
- Members are read only from the named forms. The positional second argument of `setClass("A", representation(x = "numeric"))`, `R6Class("X", list(...))` and `setRefClass("A", list(...))` creates no field or slot nodes; use `slots=` / `representation=`, `public =` / `private =` / `active =` and `fields =`.
- S4 and RefClass constructors, and the import calls, are recognised only as a bare callee: `setClass(...)`, `setRefClass(...)`, `setGeneric(...)`, `setMethod(...)`, `library(...)`, `require(...)` and `source(...)`. A namespace-qualified call such as `methods::setClass("A", slots = list(x = "numeric"))` creates no class, slot, generic or method, and `base::library("pkg")` creates no import. `R6::R6Class(...)` is recognised.
- For `S3method(generic, class, method)` the positional third argument names the registered method. A named third argument such as `S3method(print, foo, method = impl)` is not read: R registers `impl`, but the registration is recorded for `print.foo`, and `rename` treats the NAMESPACE as unreadable.

### Bounds on NAMESPACE exportPattern matching

- Matching work and NFA states are counted in deterministic work units, never wall-clock time, so the outcome is the same on every machine. A NAMESPACE file is still read in full.
- Caps, in `linear-regex.ts`: `MAX_TOTAL_WORK` (40,000,000 state visits per matcher), `MAX_SHARED_WORK` (100,000,000 matching visits per load), `MAX_PACKAGE_WORK` (30,000,000 per package), `MAX_SHARED_STATES` (500,000 NFA states per load) and `MAX_PACKAGE_STATES` (100,000 per package); a single pattern is also capped by `MAX_PATTERN_LENGTH` (16,384 characters) and `MAX_STATES` (16,384).
- A pattern refused after its NFA was partly built is charged for the build (eight visits per state or build step), and once the budget is spent later patterns are refused without being parsed (dropped, with a reason naming the work budget). A NAMESPACE of thousands of oversized patterns therefore spends the same budget as one of hostile matches.
- Groups nested deeper than 256 (`MAX_NESTING`) are refused with the reason "groups are nested too deeply". The limit sits well inside the call stack (a quarter of the default stack still compiles 256 levels), so the verdict is the same cold or warm and on every machine.
- Once the work budget is spent the matchers are no longer asked. A name an `exportPattern()` matched while the budget lasted keeps that answer (a second definition of the same name stays exported; only the first 100,000 distinct matched names per package are remembered, so past that a name reads as not exported once the budget is spent); a name not decided by then reads as not exported (fail closed), and the cut-short patterns are named in a warning.
- A verdict answered from a matcher's memo (a name asked about again) costs one visit of the work budget, so many matchers asked about the same names over and over are bounded by the budget too.
- A counted visit costs about 50 to 70 ns of real time on realistic patterns (13 ns for a hostile one, 13 ns for a memo hit; measured), so the package cap is about 2 s and the load cap about 7 s in the worst case: bounded, never a hang. No fixed per-test overhead is charged on top of the visits (it was tried and dropped, because it moved a pinned visit count and a visibility verdict; R-42).
- A file over the shared size cap (512 KB by default, `GITNEXUS_MAX_FILE_SIZE`) is skipped for every language. With the cap raised, a 50,000-line (2.4 MB) R file took about 138 s and ended with its definitions dropped, as an equivalent TypeScript file does: shared behaviour, not R-specific, left unchanged (R-41). Separately, the R query returns 1,028 matches for 1,500 nested calls (tree-sitter behaviour), so a match count is not a call count.
- A pattern that does not fit is dropped, exports nothing and is warned about: at most 50 patterns are named per package (`MAX_LISTED_DROPPED_PATTERNS`), followed by a summary line counting the rest.
- The first pattern refused for lack of states closes that package's allowance, so later patterns in the package are refused without being parsed.
- One hostile package cannot exhaust the load budget alone (it is limited to its own share), but several can (three, for matching work); packages processed after that degrade, with warnings. Which package degrades follows graph node order.
- Budget exhaustion while resolving NAMESPACE `importFrom()` names is not reported: the scope resolver loads its own configuration, consults the same matchers, and a name a cut-short pattern would have exported then reads as not exported, with no warning. The `postParse` warnings above are the only report.
- Explicit `export()` names are unaffected by these bounds.

## Control flow

R provides a control-flow-only CFG visitor (`cfg/visitors/r.ts`), used under `analyze --pdg`. It gives R `BasicBlock` nodes, `CFG` edges and control-dependence (`CDG`) edges.

Modelled, in statement position inside a function body: `if` / `else if` / `else`, `for`, `while`, `repeat`, `break`, `next`, `return(...)` and bare `{ }` blocks. Every loop, including `repeat` and `while (TRUE)`, has a structural exit edge so that EXIT stays reachable for control dependence. Each `function_definition` (`function(x)` and `\(x)`, assigned or anonymous) gets its own CFG; a nested function is opaque in its parent. An `if` arm that is missing (no `else`) or empty (`{}`) produces no block: it is the header's `seq` edge to the join, and control dependence labels it as the complement of the other arm's explicit `cond-true` / `cond-false` edge (`if (c) {} else work()` makes `work()` control-dependent on `c` with label `F`).

Not modelled:

- No def/use harvest and no binding table, so reaching definitions report `no-facts` and R emits no `REACHING_DEF` edges; no taint call sites are recorded. This is a coverage gap, not a result of "no flows found". The PDG tools do not say so for R: `pdg_query` with `mode: "flows"` returns `{"results": [], "total": 0}` with no note, `explain` returns `findings: []` with its generic absence note, and the `impact` note for `mode: "pdg"` still reads "over CDG + REACHING_DEF". Read an empty answer for an R function as "not analysed". The shared tools have no per-language capability signal to report this from, so it is documented here rather than patched into them.
- Control flow nested inside an expression stays one straight-line block: `y <- if (c) a else b`, `switch()`, `&&` / `||`, `ifelse()`, and `return()` / `break` inside `tryCatch({ ... })`, `local({ ... })` or similar wrappers.
- `stop()`, `on.exit()`, `tryCatch` handlers and other non-local exits are ordinary calls: no throw edges and no finaliser routing. A `break` / `next` with no enclosing loop falls back to EXIT.
- Function join: a CFG is anchored at the `function_definition` token, while the `Function` node starts at the whole assignment. They share a start line for `f <- function`, `f = function` and `f <- \(x)`, but not for `f <-` followed by `function` on the next line; there the CFG is still emitted and its blocks lie inside the `Function` node's span, but the exact start-line join used by taint summaries does not resolve (inert for R today, since reaching definitions have no facts). Anonymous functions have a CFG but no `Function` node.

## Rename

`languages/r/rename.ts` gives the `rename` tool a deliberately narrow, fail-closed R provider (fixtures under `test/fixtures/rename-integration/r/`). R binds names dynamically, so only what the scope graph proves is renamed.

- **Succeeds:** a plain function (`name <- function(...)`) and the calls the graph resolves to it, in one file or across files; a package function that `NAMESPACE` leaves private is included. Every parameter is claimed as a binding, whatever its default, so a parameter of the old name that the body never uses is left alone (`parameter-read-only`); a call of the name under a same-named parameter is refused (see below), and so is a body that reads it (`incomplete_semantics`, below).
- **Refused (`unsupported_occurrence`, planning status `unsupported`):**
  - any target that is not a plain `Function` (S4 classes, R6 classes, members);
  - a function whose old or new name is the whole value of a string literal anywhere in the indexed R sources (`UseMethod("area")`, `do.call("f", ...)`, `match.fun`, `get`, `setGeneric`, ...), because string lookup is not resolved. The literal is decoded first, so escapes (`"f\x6fo"`, `"\u{66}oo"`, octal) and raw strings (`r"(foo)"`) count. A string that contains a call of the name (`"foo(1)"`, glue or cli interpolation such as `"{foo(x)}"`, `parse(text = "foo(1)")`, a formula string) is refused too (`unsupported_occurrence`); a string that only mentions the name as a word, `{name}` value interpolation, a name built at run time (`paste0("fo", "o")`), and strings in files that are not indexed R sources (R Markdown, `NAMESPACE`) are not detected;
  - a new name `generic.class` where any dot-separated prefix is a function defined in the indexed R sources or a known base generic, which would register an S3 method (`to.json.foo` for a defined `to.json`, `print.foo`). The known generics are the S3 group generics (`Ops`, `Math`, `Summary`, `Complex`, `matrixOps`) with every function each group dispatches (`sum.items`, `abs.diff`), the `is.*` and `as.*` generics (`is.numeric.foo`, `as.complex.foo`), and the common generics of base, stats, graphics and utils (`print`, `format`, `summary`, `plot`, `unlist`, `pretty`, `weighted.mean`, ...). Generics of other packages (`tidy`, `filter`, ...) are not listed;
  - an infix function or operator, as the old or the new name (`` `%+%` ``, `` `%||%` ``, `` `+` ``, `` `[[` ``): `a %+% b` is an operator token, not an identifier, so a rename would edit only the definition;
  - a replacement function and its getter (`unsupported_occurrence`): a call of the name anywhere in an assignment target (`helper(z) <- 5`, `helper(z)$a <- 1`, `names(helper(z)) <- v`, the `->` forms), because R then calls `` `helper<-` ``; an old or new name ending in `<-`; and a string-defined setter (`"helper<-" <- function(...)`) of either name;
  - a new name that is already a global (`name_collision`): a top-level variable or function of that name in any indexed file (`assist <- 3`, a `for` variable, `3 -> assist`), a `<<-` or `->>` to it anywhere, or a function of that name in another file. Same-file function collisions were already refused by the shared engine; local variables, parameters and members of that name are allowed;
  - a new name that the sources already read as a value or call (`name_collision`): `sapply(x, paste)`, `Reduce(max, x)`, `x <- letters`, a default `f = assist`, a formula term, `assist[1]`, `assist(1)`. After the rename the function is the global of that name and would capture the read. A parameter of an enclosing function of that name covers a plain read but not a call: a default proves nothing about the argument, so a call of the new name under such a parameter may reach the global the renamed function becomes. Not reads: bound names, argument names (`f(assist = 1)`), members (`x$assist`, `x@assist`) and qualified names (`pkg::assist`);
  - a call of the name under a same-named parameter (`ambiguous_reference`), whatever its default (none, a constant, `NULL`, a function or a computed value) and whether or not the body assigns it, because the call may reach the parameter or the function being renamed;
  - a function while a same-named parameter is read in a body (`function(x, helper) x + helper`), or a `for` variable of that name is called in a loop (`incomplete_semantics`; fixtures `parameter-body-read`, `for-variable-call`): no edge covers the occurrence, so the planner stops; it never renames and leaves the call behind (R-16);
  - a function body that assigns the name a value that may be a function (`ambiguous_reference`; `helper <- identity`, `helper = f()`, `identity -> helper`, `helper$a <- v`), whether or not the name is called there and wherever the assignment sits relative to a call, because the local may shadow the function being renamed (the call-resolution side treats the same assignments as lexical names, see Calls). A function literal (`helper <- function(y) 2`) is a separate definition and does not refuse when it is defined first (see the local-definition guard below); a constant (`helper <- 2`) is not read as a binding, so the shared engine refuses it as an uncovered occurrence (`incomplete_semantics`);
  - a function that is also assigned with `<<-` or `->>` anywhere in the indexed R sources (`ambiguous_reference`, as the top-level form already was): the global re-assignment is a second definition that a rename would leave behind;
  - a package function under `R/` that is not proven private, because `NAMESPACE` is not an indexed source and its entry would not be renamed. Two checks must both pass. The persisted `isExported` flag must be false, which it is only for a function that a `NAMESPACE` file beside the package leaves out of `export()`, `exportPattern()` and `S3method()` (the third argument of `S3method(generic, class, method)` counts): a package with no `NAMESPACE` file, or an `R/` folder that belongs to no package, keeps the default public flag and is refused. That includes projects that keep their functions in `R/` without a `DESCRIPTION` (targets, drake and analysis repositories): every rename of a function under `R/` is refused there, and a function outside `R/` is not. The flag is not enough alone, because an edit of `NAMESPACE` with no `R/` file touched leaves it stale until a full analyse. So every rename plan also reads the package's `NAMESPACE` from disk again, through the parsing the indexer uses, and refuses (`unsupported_occurrence`) when it now exports the name by `export()`, `exportPattern()` or `S3method()`. It fails closed with `incomplete_semantics` when that `NAMESPACE` was deleted or cannot be read, when an `exportPattern()` of it was dropped or ran out of work budget (a name such a pattern was meant to cover is then not provably private), or when the reader skipped or could not read something that may hide an export: a conditional `if (...) export(x)`, a raw-string or multi-line argument, an argument that is an expression, an `S3method()` it cannot read, or a malformed directive that swallowed an export. It also refuses (`unsupported_occurrence`) a function whose roxygen2 block (the `#'` lines directly above the definition) carries `@export`, `@exportMethod`, `@exportS3Method` or another `@export*` tag, because the next `document()` would export the new name; the tag is found by text, other roxygen2 tags (`@rdname`, `@inheritParams`, `@seealso`) are not read. A private function in a package whose `NAMESPACE` is unchanged is renamed; a script outside `R/` is not affected. The check does not need `--force`; re-run `analyze` to bring the flag itself up to date. The persisted flag stays a second check on purpose, although the plan-time read decides the stale-private case on its own: it costs nothing, it needs no NAMESPACE read to answer, and when it is stale the other way round (the index says exported, NAMESPACE no longer does) it refuses until the next analyse, which is the safe direction.
  - a bare call of the name inside a method of a portable R6 class that defines a member of that name (`ambiguous_reference`): a bare call in a portable method does not see class members, so it reaches the function being renamed but has no proven edge. A class with `portable = FALSE` is not refused;
  - a name defined at top level in more than one file of the same load unit (`ambiguous_reference`; the same package, or both files outside every package): load order decides which definition callers reach. Definitions inside functions and inside block scopes (`local`, `test_that`, `with`, ...) do not count;
  - an R file the index does not cover that uses the name, or that cannot be read in full (`incomplete_semantics`). The rename preview walks the repository for `.R`/`.r` files in directories the indexer skips (`bin/`, `build/`, `tmp/`), `.gitignore`d files, files over the indexer's size cap, `.Rprofile` and the `.S`/`.q`/`.s` code files under `R/`, and records their identifier tokens; a file over 8 MB or one that cannot be read fails closed. Not scanned: `.git`, the index store, `node_modules`, `*.Rcheck`, `renv/library`, `packrat/lib*`, whatever `.gitnexusignore` excludes, extensionless Rscript files and R Markdown code. Editing a scanned file between preview and apply makes the apply fail as `resolution_changed`. The tokens of every unindexed file are retained with the plan, so a very large unindexed R tree can push the retained plan past its budget, and the preview then fails closed with `plan_too_large` (measured as an upper bound, treating every file as unindexed: 511 R files, 59,468 tokens, use 4.06% of the 64 MiB budget; the 6,378 R files of this repository, fixtures included, use 117%; R-38);
  - a function whose body defines the name as a function literal, unless the definition is a direct statement of the body (not under `if`, `switch`, a loop, `tryCatch` or any call) and every call of the name in that body, nested functions included, starts after it (`ambiguous_reference`: a call may run before the local definition). A function with no call of the name is not refused, and a call inside the qualifying literal itself (recursion) is ignored (R-39). A top-level call of the name that precedes the top-level definition, in the file or in a script that attaches it, is refused too, because it reaches another function of that name;
  - a new name that `NAMESPACE` already exports through `export()` or `exportPattern()` (`unsupported_occurrence`): the rename would change the package API;
  - a generated file (`unsupported_occurrence`): the target file, or any indexed R file in which the name occurs as an identifier, has \"Generated by\" or \"do not edit by hand\" in its first five lines (`RcppExports.R`, `cpp11.R`), because the generator would restore the old name;
  - a call of the name inside a `setRefClass(..., methods = list(...))` method of a class with `contains =` when a class of the chain defines a method or field of that name, or when a parent is not indexed (other than `envRefClass` and `VIRTUAL`) (`ambiguous_reference`): the call may reach the inherited member;
  - a roxygen2 `@rawNamespace` line, or an `@export <name>` line, of the package that names the function (`unsupported_occurrence`): the next `document()` would write the old name into `NAMESPACE`.
- **Not updated by a successful rename:** files that are not indexed R sources. R Markdown and Quarto documents (`.Rmd`, `.qmd`, vignettes, `README.Rmd`), `man/*.Rd` (`\alias`, `\usage`), roxygen2 tags that name the function (`@rdname`, `@inheritParams`, `@seealso`), `_pkgdown.yml`, `pkg:::name` uses in `inst/`, and C++ or other code that looks it up by string keep the old name. So does code that reads the name off the call: `match.call()`, `deparse(substitute(f))` and snapshot tests of printed calls (R-37). The result does not list them; search for the old name in those files after a rename.
- **Refused by the shared engine (fail-closed, not provider code):** S3 methods and any function name with a dot after its first character (`area.circle` reads as an owner-qualified member, so `stale_graph`). A name whose only dot is the leading one (`.helper`, the usual internal-function convention) is renamed like any other function, with one exception: R's hook functions `.onLoad`, `.onAttach`, `.onUnload`, `.onDetach`, `.First`, `.Last`, `.First.sys`, `.First.lib` and `.Last.lib` are refused (`unsupported_occurrence`), because R calls them by name; S4 class names (`unsupported_occurrence`, no exact source-name span).
- **Invalid names (`invalid_name`):** anything that is not a nonreserved R identifier: the reserved words, `...` and `..1`, `..2`, ..., and any name with a non-ASCII character, because new names are limited to ASCII letters, digits, `.` and `_` (conservative by design; the message says so). An old name made only of non-ASCII characters (`λ`) is refused as not a supported identifier. Backtick-quoting a new name is never offered: a name that needs it is refused rather than quoted at every use.
- **Refused when any indexed R file does not parse (`parse_error`):** the rename plan parses every indexed R file, and a syntax error in one of them, related to the target or not, refuses the rename and names that file. Fix the file (or exclude it) and plan again.
- **Not proven:** unqualified calls to a function defined in another file (including the package `R/` layout) fail with `ambiguous_reference`, because R's global-name fallback is not a provable binding. Renaming across files works only where the call is qualified or otherwise resolved.

## Type annotations

R has no inline type annotations, so the "Type Annotations" column of the language support table is not ticked for R. The roxygen2 `@param` extraction above is a comment-based fallback, in the same class as the JSDoc, PHPDoc and YARD fallbacks listed in type-resolution-system.md (Ruby's YARD support is likewise not ticked).

## Extending the provider

- Definition captures are in `R_QUERIES` (`tree-sitter-queries.ts`); scope, import, type-binding, heritage and reference captures are in `languages/r/query.ts`. Keep each declaration pattern and its matching `@scope.function` pattern in lockstep, as the comments in `query.ts` explain.
- The captures for `setClass`, `setRefClass`, `setGeneric`, `setMethod` and for `library` / `require` / `source` are deliberately loose. The argument that names the definition or the import is chosen afterwards in `languages/r/naming-argument.ts`, because a query-level prefix that skips leading comments and named arguments is quadratic in the argument count.
- Resolution wiring is in `languages/r/scope-resolver.ts`, registered in `SCOPE_RESOLVERS`. Import resolution is in `import-target.ts`; package discovery and NAMESPACE parsing are in `package-config.ts` and `namespace-imports.ts`; qualified calls in `qualified-call.ts`; owner and export post-processing in `post-parse.ts` and `owner-hooks.ts`.
- Changing what the scope query captures changes what cached parsed files contain. There is no counter to raise: the parse-cache identity is derived from the bytes of the owned source roots and the grammar packages, so the change invalidates stale caches by itself. Rebuild `dist` and verify a cold parse followed by warm reuse, as CONTRIBUTING's "Parser changes and cache compatibility" section describes.
- Shared code under `gitnexus/src/core/ingestion/` must not name languages; add behaviour through the provider hooks.

Unit tests are under `gitnexus/test/unit/` (`r-*.test.ts`, `type-env-r.test.ts` and `scope-resolution/r/`) and integration tests under `gitnexus/test/integration/resolvers/` (`r*.test.ts`), with `r-*` fixture projects in `gitnexus/test/fixtures/lang-resolution/`. They cover:

- definitions, owners and the naming-argument rules (`r-definition-anchors`, `r-owner-hooks`, `r-post-parse-owners`, `r-scope-naming-argument`, `r-s4-anchors`, `r-s4-formals`, `r-scope-args`);
- NAMESPACE parsing, exports and `exportPattern()` safety and scale (`r-namespace-parser`, `r-namespace-exports`, `r-export-pattern*`, `r-export-status-*`);
- package discovery and root-package imports (`r-package-discovery-*`, `r-import-root-package`, `r-namespace-imports`);
- qualified calls, exports and visibility, dotted S3 names and native pipes (`r-qualified-*`, `r-qualified-exports`, `r-qualified-visibility`, `r-dotted-s3-collision`, `r-native-pipes` fixture in `r.test.ts`);
- receivers, `self` and chains (`r-self-binding`, `r-chained-receivers`, `r-receiver-chain`, `r-call-shapes`, `r-receiver-agreement`, `r-typed-receiver-members`) and the receiver corpus (`r-receiver-corpus`: one table of call shapes with exact expected targets, decoys and recorded outcomes, summarised in [r-ingestion-gaps.md](r-ingestion-gaps.md));
- lexical names, block scopes, assignments and replacement calls (`r-lexical-names`, `r-formal-shadows`, `r-assignment-locals`, `r-rename-assigned-locals`, `r-replacement-calls`, `r-block-scopes`);
- package visibility, S3 registration and S4 generators (`r-package-visibility`, `r-s3method-registration`, `r-s4-generator`);
- work bounds and pathological inputs (`r-replacement-scaling`, `r-pathological-inputs`);
- the shared free-call ordering that lets a qualified hit outrank a lexical name claim (`free-call-qualified-over-name-claim`, `rust-qualified-over-local`, `php-qualified-over-local`);
- rename (`rename-provider-r` and `rename-provider-r-part2`, which split one fixture list in two so each shard stays inside the CI time budget; `r-rename-*`, including `r-rename-unindexed-sources`);
- roxygen2 `@param` types (`type-env-r`, `r-roxygen-param`);
- control flow (`test/unit/cfg/r-visitor.test.ts`, `test/integration/cfg/r-cfg-join.test.ts`).
