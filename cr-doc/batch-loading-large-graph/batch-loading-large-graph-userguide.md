# 大型图谱分批加载 - 用户手册

## 概述

GitNexus Web 现在支持大型项目的智能分批加载。当项目边数超过 100,000 时，系统会自动切换为分批加载模式，大幅提升加载性能和用户体验。

---

## 功能特性

### ✅ 智能模式切换
- **小型项目**（边数 ≤ 100,000）：保持原有全量加载
- **大型项目**（边数 > 100,000）：自动分批加载

### ✅ 进度可视化
- 显示当前批次 / 总批次
- 显示加载阶段：Fetching / Merging / Rendering
- 百分比进度条平滑增长

### ✅ 性能优化
- 节点自动去重
- 边数据流式合并
- UI 线程不阻塞

---

## 使用场景

### 适用于大型项目
推荐在以下情况下使用：
- 代码库规模 > 5,000 个符号
- 边数 > 100,000
- 原有加载方式耗时过长

### 示例项目规模
| 项目类型 | 节点数 | 边数 | 推荐模式 |
|---------|--------|------|---------|
| 小型库 | < 1,000 | < 10,000 | 全量加载 |
| 中型项目 | 1,000-5,000 | 10,000-100,000 | 全量加载 |
| 大型项目 | 5,000-20,000 | 100,000-500,000 | 分批加载 ✨ |
| 超大项目 | > 20,000 | > 500,000 | 分批加载 ✨ |

## 操作指南

### 1. 启动服务器

```bash
cd gitnexus
npx gitnexus analyze
npx gitnexus serve
```

### 2. 连接前端

访问以下 URL：
```
http://localhost:5173/?server=http://localhost:4747&localWasm=false
```

**参数说明**：
- `server`: GitNexus 服务器地址
- `localWasm=false`: 使用纯服务器模式（推荐大型项目）

### 3. 观察加载过程

#### 小型项目（< 100,000 边）

## 进度展示说明

### 批次信息
- **Batch X / Y**：当前批次 / 总批次
  - 例如：`Batch 2 / 3` 表示正在加载第 2 批，总共 3 批

### 加载阶段
- **Fetching edges...**：从服务器获取边数据
- **Merging data...**：合并节点和边数据
- **Rendering...**：准备渲染图谱

### 百分比进度
- 基于已处理的边数计算
- 平滑过渡，避免跳跃

## 常见问题 (FAQ)

### Q1: 如何判断我的项目是否适合分批加载？

**A**: 系统会自动判断。如果您看到进度条显示 "Loading large graph (batch X/Y)..."，说明已经进入分批加载模式。

一般来说：
- 边数 > 100,000 时自动启用
- 可以在控制台查看边数：`result.repoInfo.stats.edges`

---

### Q2: 分批加载会影响数据完整性吗？

**A**: 不会。分批加载只是改变了数据传输方式，最终加载的节点和边数量与全量加载完全一致。

系统会自动：
- 去重节点（避免重复）
- 合并所有批次的边
- 验证数据完整性

---

### Q3: 可以中途取消加载吗？

**A**: 可以。刷新页面或关闭标签页即可取消加载。已加载的数据会被清理，不会造成内存泄漏。

---

### Q4: 分批加载后查询会变慢吗？

**A**: 不会。分批加载只影响初始数据加载，不影响后续查询性能。

查询性能取决于：
- 使用 `localWasm=false`：查询走服务器 API
- 使用 `localWasm=true`：查询走本地 WASM 数据库

---

### Q5: 为什么第一批加载快，后面越来越慢？

**A**: 这是 Cypher `SKIP` 深分页的正常现象。随着 offset 增大，数据库需要跳过更多记录，性能会有所下降。

影响有限：
- 第 1 批：~5 秒
- 第 3 批：~8 秒
- 第 10 批：~15 秒

后续版本会优化为游标分页，消除此问题。

---

### Q6: 网络中断了怎么办？

**A**: 系统会显示错误提示。您可以：
1. 检查网络连接
2. 刷新页面重新加载
3. 确保 GitNexus 服务器正在运行

## 故障排除

### 问题 1: 加载一直卡在某个批次

**可能原因**：
- 网络不稳定
- 服务器响应慢
- 该批次数据量特别大

**解决方法**：
1. 打开浏览器控制台（F12）查看错误信息
2. 检查网络标签，确认请求状态
3. 如果超时，刷新页面重试
4. 检查服务器日志

---

### 问题 2: 加载完成后节点数量不对

**可能原因**：
- 数据去重逻辑异常
- 服务器返回数据不完整

**解决方法**：
1. 在控制台运行验证代码：
   ```javascript
   const nodeIds = new Set(graph.nodes.map(n => n.id));
   console.log(`节点数: ${graph.nodes.length}, 唯一节点数: ${nodeIds.size}`);
   ```
2. 对比 `stats.edges` 和实际边数
3. 如发现问题，请提供日志反馈

---

### 问题 3: 进度条不更新

**可能原因**：
- UI 线程被阻塞
- 进度回调未正确触发

**解决方法**：
1. 刷新页面重试
2. 检查浏览器兼容性（建议使用 Chrome/Edge 最新版）
3. 查看控制台是否有 JavaScript 错误
